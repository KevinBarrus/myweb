## 一、前置知识

1. **磁盘**：永久存储，关机数据不丢，慢
2. **内存（Buffer Pool）**：临时缓存，操作都先在这，快

## 二、磁盘上存了什么（关键 3 个文件）

1. **.ibd 文件**
    
    每张表独立的表空间文件：存**表数据 + 所有索引**（聚簇索引、二级索引全在这）。
2. **redo log 日志文件**
    
    崩溃恢复用的，保证事务不丢数据，写操作先写日志，再刷数据到磁盘。
3. **undo log 日志**
    
    事务回滚、MVCC 多版本读依赖它，保存数据修改前的旧版本。

## 三、内存核心：Buffer Pool（缓冲池）

**这是 InnoDB 性能的命根子**。

你可以把它理解成：**磁盘数据的高速临时副本缓存**。

### Buffer Pool 存什么？

- 从磁盘加载进来的**数据页**
- 从磁盘加载进来的**索引页**

单位不是一行一行，是 **页（Page）**

默认一页 16KB，InnoDB 读写最小单位就是**页**。

### 一条查询的真实流程

1. 执行器让 InnoDB 查某行数据
2. InnoDB 先去 **Buffer Pool 内存** 找：
    
    - 找到了 → 直接返回，**不走磁盘，极快**
    - 没找到 → 从磁盘把整**16KB 数据页**加载进 Buffer Pool，再从页里找出你要的行返回
    
3. 后续别人再查同一页数据，直接命中内存

### 一条更新的真实流程

1. 先把数据页加载到 **Buffer Pool 内存**
2. **只改内存里的数据**（此时磁盘上还是旧数据）
3. 同时写 **redo log** 记录这次修改
4. 后续后台线程慢慢把内存脏页**异步刷回磁盘**

👉 关键：

**更新不是直接改磁盘，是改内存 + 记日志，后台慢慢落盘**，这是 MySQL 快的根本原因。

## 四、两个关键概念

1. **干净页**：内存和磁盘数据一模一样，不用刷盘
2. **脏页**：内存改了，磁盘还是旧的，需要后台刷到磁盘
