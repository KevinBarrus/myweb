### 0/1 Knapsack and Unbounded Knapsack

### 0/1 Knapsack

Scenario: there are `n` items and a knapsack with capacity `bagweight`. The weight of item `i` is `weight[i]`, its value is `value[i]`, and each item can be used only once. Find the maximum total value of the items placed in the knapsack.

Brute force: each item is either selected or not selected. Use backtracking. The time complexity is `O(2^n)`.

Therefore, use dynamic programming for optimization. First clarify the dimensions and meaning of `dp`. Since both items and their weights must be considered, start with a two-dimensional array. In `dp[i][j]`, `i` is the item index, `j` is the knapsack capacity, and `dp[i][j]` is the maximum total value obtainable by selecting any items from indices 0 through `i` with a knapsack of capacity `j`.

Next, determine the recurrence.

Use the derivation of `dp[2][3]` as an example:

`dp[2][3]` means the maximum total value obtainable with a capacity-3 knapsack by selecting any items with indices 0, 1, and 2. To solve it, there are two cases: place item 2 or do not place item 2.

If item 2 is not placed, its presence has no effect, so `dp[2][3] = dp[1][3]`.

If item 2 is placed, enough space must be reserved. If its weight exceeds 3, it cannot be placed. Otherwise, suppose its weight is 2. A capacity-3 knapsack has capacity 1 remaining after placing it, so we only need the maximum value obtainable from items 0 and 1 with capacity 1: `dp[2][3] = dp[1][1] + value[2]`.

In general:

Do not place item `i`: `dp[i][j] = dp[i-1][j]`.

Place item `i`: `dp[i][j] = dp[i-1][j-weight[i]] + value[i]`.

Take the maximum of the two.

Initialize the `dp` array because `i` is derived from `i-1`:

`dp[i][0]`: capacity is 0, so no item can be placed; initialize it to 0.

`dp[0][j]`: only item 0 can be selected. If `j < weight[0]`, initialize it to 0; otherwise initialize it to `value[0]`.

The recurrence shows that all other indices can be derived from values above and to the left, so elements in all other positions can be initialized to 0 by default.

Therefore, initialization only needs to process row 0; everything else is initialized to 0.

Now consider the traversal order of the `dp` array.

Should items or knapsack capacity be traversed first? Either order works, because each result is derived either from directly above or from the upper left.

Item first:
```c++
for(int i=1;i<weight.size();i++) {
    for(int j=0;j<=bagweight;j++) {
        if (j<weight[i]) dp[i][j]=dp[i-1][j];
        else dp[i][j]=max(dp[i-1][j],dp[i-1][j-weight[i]]+value[i]);
    }
}
```

Capacity first:
```c++
for(int j=0;j<=bagweight;j++) {
    for(int i=1;i<weight.size();i++) {
        // same as above
    }
}
```

#### Rolling Array

From the two-dimensional recurrence, `dp[i][j]` only depends on `dp[i-1][j]` and `dp[i-1][j-weight[i]]`. Because the previous row, namely `i-1`, can be copied through a rolling array, we can optimize it into a one-dimensional array.

The optimized recurrence is `dp[j] = max(dp[j-weight[i]]+value[i], dp[j])`.

The `dp[j]` inside the parentheses is the previous row's `dp[j]`, equivalent to `dp[i-1][j]`.

Next, consider how to initialize this one-dimensional array. `dp[j]` is the maximum value of items that a capacity-`j` knapsack can hold. Therefore, `dp[0]=0`, while every other position can be derived from preceding positions, so every position only needs to be initialized to 0.

Now consider the traversal order: traverse items first, and then traverse knapsack capacity in reverse order.

When using a rolling array, the inner loop must traverse in reverse. With forward traversal, the same item may be placed more than once. Because every update of the `dp` array considers whether item `i` should be added to the knapsack, if an earlier-capacity knapsack has already added item `i`, it no longer makes sense for a later position to consider adding item `i` again. Reverse traversal avoids this problem because `dp[j]` depends on preceding elements.

For example: `weight[0]=1, value[0]=20`.

With forward traversal, during the first traversal, `dp[1]=dp[1-weight[0]]+value[0]=20`.

Then `dp[2]=dp[2-weight[0]]+value[0]=40`.

However, `dp[2]` means the maximum value that can be placed into a capacity-2 knapsack when item 0 is available. Clearly, item 0 can only be selected once, so the maximum value should be 20. It becomes 40 here because the item was counted twice.

Only reverse traversal lets us find the true `dp[i-1][j-weight[i]]`. Because we need the element from the previous row, we must not overwrite it first.

If capacity is traversed first, the code is:
```c++
for(int j=bagweight;j>=1;j--) {
    for(int i=0;i<weight.size();i++) {
        if(j>=weight[i]) dp[j]=max(dp[j],dp[j-weight[i]]+value[i]);
    }
}
```

Assume `bagweight=5`. There are three items with weights 1, 2, and 3 and values 1, 2, and 3.

At first, `j=5`, and the inner loop begins:

When `i=0`, `j >= weight[0]=1`, so `dp[5]=dp[5-1]+value[0]=0+1=1`.

When `i=1`, `j >= weight[1]=2`, so `dp[5]=max(dp[5],dp[5-2]+2)=2`.

At this point, something is clearly wrong. A capacity-5 knapsack can hold both the weight-1 and weight-2 items, whose total value should be 3, but the value is only 2 when `i=1`.

If items are traversed first and knapsack capacity second:
```c++
for(int i=0;i<weight.size();i++) {
    for(int j=bagweight;j>=weight[i];j--) {
        dp[j]=max(dp[j],dp[j-weight[i]]+value[i]);
    }
}
```

Again assume `bagweight=5`, with three items whose weights are 1, 2, and 3 and whose values are 1, 2, and 3.

In the first round, `i=0`, and the inner loop begins.

At `j=5`, `dp[5]=dp[4]+1=1`.

At `j=4`, `dp[4]=dp[3]+1=1`.

The same pattern continues. In this round, every value except `dp[0]=0` is 1, because only item 0 can be selected and selecting it always has a higher value than not selecting it.

In the second round, `i=1`, and the inner loop begins.

At `j=5`, `dp[5]=max(1,dp[3]+2)=3`.

Now the knapsack has truly placed both item 0 and item 1.

In general, because reverse traversal is required, traversing knapsack capacity before items means that the preceding capacities have not yet been processed, so it is equivalent to being able to place only one item at a time.

Therefore, items must be traversed first, followed by knapsack capacity.

### Unbounded Knapsack

Scenario: there are `N` items and a capacity-`bagweight` knapsack. Item `i` has weight `weight[i]` and value `value[i]`, and every item can be used infinitely many times. Find the maximum total value.

The meaning of the `dp` array is the same as in 0/1 knapsack. Consider the recurrence directly.

There are two cases when solving `dp[i][j]`:

1. Do not choose item `i`: `dp[i-1][j]`.
2. Choose item `i`: because it may be chosen repeatedly, `dp[i][j] = dp[i][j-weight[i]] + value[i]`.

Take the maximum of the two.

Now consider initialization.

`dp[i][0]` must be 0 because a knapsack with capacity 0 cannot hold anything.

`dp[0][j]` means the maximum value that knapsacks of different capacities can hold when only item 0 is available.

When `j < weight[0]`, `dp[0][j]=0`, because the capacity is insufficient to hold one copy of item 0.

When `j >= weight[0]`, keep placing item 0 into the knapsack until no more copies fit.

As in the initialization of the 0/1 knapsack `dp` array, all other positions can be initialized directly to 0 because they are derived from the upper-left or directly above.

The initialization code is:

```c++
vector<vector<int>>dp(weight.size(),vector<int>(bagweight+1,0));

for(int j=weight[0];j<=bagweight;j++) {
    dp[0][j]=dp[0][j-weight[0]]+value[0];
}
```

The traversal order can also be either knapsack first and items second, or items first and knapsack second.

#### Rolling Array

The recurrence for the two-dimensional array is `dp[i][j]=max(dp[i-1][j],dp[i][j-weight[i]]+value[i])`.

After compression into a one-dimensional array, the recurrence is `dp[j]=max(dp[j],dp[j-weight[i]]+value[i])`.

In 0/1 knapsack, reverse capacity traversal prevents an item from being used repeatedly. In unbounded knapsack, repeated use is allowed, so capacity need not be traversed in reverse and the order is not strictly restricted.

```c++
for(int i=0;i<weight.size();i++) {
    for(int j=0;j<=bagweight;j++) {
        if(j>=weight[i]) dp[j]=max(dp[j],dp[j-weight[i]]+value[i]);
    }
}
```

Reverse traversal is also possible, in which case the `if` check is unnecessary.

#### Problem 1

Problem link: [416. Partition Equal Subset Sum - LeetCode](https://leetcode.cn/problems/partition-equal-subset-sum/description/)

You are given a **non-empty** array `nums` containing **only positive integers**. Determine whether the array can be divided into two subsets whose element sums are equal.

**Example 1:**

```
Input: nums = [1,5,11,5]
Output: true
Explanation: The array can be partitioned into [1, 5, 5] and [11].
```

**Example 2:**

```
Input: nums = [1,2,3,5]
Output: false
Explanation: The array cannot be partitioned into two subsets with equal sums.
```

**Constraints:**

- `1 <= nums.length <= 200`
- `1 <= nums[i] <= 100`

This problem can obviously be solved with backtracking, but that is too slow.

In fact, we only need to find a subset whose sum is `sum/2`. In other words, we now have a knapsack with capacity `sum/2`, and only need to determine whether some collection of numbers can fill it. Each number is an item, and both its value and weight are equal to that number.

We still calculate the maximum value that the knapsack can hold and then check whether that maximum equals the capacity. This returns us to the earlier template.

1. Determine the meaning of the `dp` array

`dp[j]` is the maximum value of items that a capacity-`j` knapsack can hold.

When `dp[k]==k`, the knapsack is full.

2. Determine the recurrence

`dp[j]=max(dp[j],dp[j-weight[i]]+value[i])`.

Here, `weight[i]==value[i]==nums[i]`, so:

`dp[j]=max(dp[j],dp[j-nums[i]]+nums[i])`.

3. Initialization

Initialize the values to 0. The maximum sum is 20000, so initializing the size to 10005 is sufficient.

4. Determine the traversal order

According to the preceding template, items must be traversed first, followed by knapsack capacity in reverse order.

The code is:

```c++
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum=accumulate(nums.begin(),nums.end(),0);
        if(sum%2==1) return false;
        int target=sum/2;
        vector<int>dp(10005,0);
        for(int i=0;i<nums.size();i++) {
            for(int j=target;j>=nums[i];j--) {
                dp[j]=max(dp[j],dp[j-nums[i]]+nums[i]);
            }
        }
        return dp[target]==target;
    }
};
```

Thus, 0/1 knapsack can be used not only to calculate maximum value, but also to determine whether the knapsack can be filled exactly.

#### Problem 2

Problem link: [518. Coin Change II - LeetCode](https://leetcode.cn/problems/coin-change-ii/description/)

You are given an integer array `coins` representing coins of different denominations and an integer `amount` representing a total amount of money.

Return the number of coin combinations that make up the total amount. If no combination can make up that amount, return `0`.

Assume that there are infinitely many coins of every denomination.

The test data guarantees that the result fits in a signed 32-bit integer.

**Example 1:**

```
Input: amount = 5, coins = [1, 2, 5]
Output: 4
Explanation: There are four ways to make up the total amount:
5=5
5=2+2+1
5=2+1+1+1
5=1+1+1+1+1
```

**Example 2:**

```
Input: amount = 3, coins = [2]
Output: 0
Explanation: Using only coins of denomination 2 cannot make up amount 3.
```

**Example 3:**

```
Input: amount = 10, coins = [10]
Output: 1
```

**Constraints:**

- `1 <= coins.length <= 300`
- `1 <= coins[i] <= 5000`
- All values in `coins` are **unique**
- `0 <= amount <= 5000`

This is similar to the previous problem: given a target number and some values, determine whether a collection of values can sum to the target. It is a typical knapsack problem, except this is an unbounded knapsack and a value can be placed into the knapsack multiple times.

The meaning of the array is: `dp[i][j]` is the number of ways to make total amount `j` using coins 0 through `i`.

This suddenly seems almost identical to climbing stairs. In climbing stairs, you can climb only 1 or 2 steps at a time. Here, the number of steps you can climb is an element in the `coins` array, the destination is `amount`, and we ask how many ways there are to climb the stairs.

If you can only climb 1 or 2 steps, then `dp[n]=dp[n-1]+dp[n-2]`. Here, the possible step sizes are an array, so we can traverse it:

```c++
for(int j=1;j<=amount;j++) {
    for(int i=0;i<coins.size();i++) {
        if(j>=i) dp[j]+=dp[j-coins[i]];
    }
}
```

But remember: if `amount=3`, taking 2 then 1 and taking 1 then 2 are different answers. Climbing stairs therefore counts permutations, while this problem asks for combinations.

This analogy still gives us an insight. To calculate `dp[i][j]`, there are two cases: coins 0 through `i` already make `j-coins[i]`, or coins 0 through `i-1` already make `j`.

This is like climbing 14 steps with possible steps of 1, 2, 3, and 4. In the first case, you have climbed 10 steps and only need to climb 4 more. In the second case, you have climbed `3+3+3+3+2`, reaching 14 without ever taking a step of 4.

Therefore, the recurrence is `dp[i][j]=dp[i-1][j]+dp[i][j-coins[i]]`.

Clearly, `j` must be bounded. If `j < coins[i]`, perhaps you can climb 1, 2, 3, or 4 steps at a time, but now only need to reach step 2. Then `dp[4][2]=dp[3][2]`, and you do not need to take a step of 3, so `dp[3][2]=dp[2][2]`.

After determining the recurrence, initialize the array. We derive values from above and from the left, so initialize the first row and first column.

The first row is `dp[0][j]`, the number of ways to make amount `j` using only coin 0. If `j` is a multiple of `coins[0]`, the number of ways is 1; otherwise it is 0.

The first column is `dp[i][0]`, the number of ways to make amount 0 using coins 0 through `i`. It is 1, because using no coins is one way. This may sound too quick, so return to the stairs example: if you can climb 1, 2, 3, or 4 steps and need the number of ways to climb 4 steps, when `i=4`, `j-coins[i]` is 0 and taking one step of 4 is valid. If `dp[i][0]` were initialized to 0, we would miss the case where one coin fills the knapsack.

With a two-dimensional array, traversal order does not matter.

Code:

```c++
class Solution {
public:
    int change(int amount, vector<int>& coins) {
        vector<vector<uint64_t>>dp(coins.size(),vector<uint64_t>(amount+1,0));
        for(int j=0;j<=amount;j++) {
            if(j%coins[0]==0) dp[0][j]=1;
        }
        for(int i=0;i<coins.size();i++) {
            dp[i][0]=1;
        }
        for(int i=1;i<coins.size();i++) {
            for(int j=0;j<=amount;j++) {
                if(j<coins[i]) dp[i][j]=dp[i-1][j];
                else dp[i][j]=dp[i-1][j]+dp[i][j-coins[i]];
            }
        }
        return dp[coins.size()-1][amount];
    }
};
```

The result overflowed twice: I first used `int`, then changed to `long long`, which was still insufficient. `uint64_t` is needed because the sum can be large.

Now consider optimization with a one-dimensional array.

Determine the meaning of the array: `dp[j]` is the total number of ways to make amount `j`.

According to the recurrence for the two-dimensional array, the one-dimensional recurrence is `dp[j]+=dp[j-coins[i]]`.

Initialization: `dp[0]` is the total number of ways to make amount 0. As explained above, initialize it to 1.

Traversal order: assume `coins={1,2}` and `amount=3`.

If coins are traversed first, followed by knapsack capacity:

```c++
for(int i=0;i<coins.size();i++) {
    for(int j=coins[i];j<=amount;j++) {
        dp[j]+=dp[j-coins[i]];
    }
}
```

In the first round, `i=0` and `coins[i]=1`:

At `j=1`, `dp[1]+=dp[0]`, producing 1.

At `j=2`, `dp[2]+=dp[1]`, producing 1.

At `j=3`, `dp[3]+=dp[2]`, producing 1.

Every value is 1 because only coins of denomination 1 can be used.

In the second round, `i=1` and `coins[i]=2`:

At `j=2`, `dp[2]+=dp[0]`, producing 2.

At `j=3`, `dp[3]+=dp[1]`, producing 2.

If knapsack capacity is traversed first, followed by coins:

```c++
for(int j=0;j<=amount;j++) {
    for(int i=0;i<coins.size();i++) {
        if(j>=coins[i]) dp[j]+=dp[j-coins[i]];
    }
}
```

In the first round, `j=0`:

Because `j<coins[i]`, this round has no effect.

In the second round, `j=1`:

When `i=0`, `coins[i]=1`, so `dp[1]+=dp[0]`, producing 1.

When `i=1`, the value remains unchanged.

In the third round, `j=2`:

When `i=0`, `coins[i]=1`, so `dp[2]+=dp[1]`, producing 1.

When `i=1`, `coins[i]=2`, so `dp[2]+=dp[0]`, producing 2.

In the fourth round, `j=3`:

When `i=0`, `dp[3]+=dp[2]`, producing 2.

When `i=1`, `dp[3]+=dp[1]`, producing 3.

The latter has clearly become the climbing-stairs problem. This shows that traversing knapsack capacity first and coins second counts permutations rather than combinations.

```c++
class Solution {
public:
    int change(int amount, vector<int>& coins) {
        vector<uint64_t>dp(amount+1,0);
        dp[0]=1;
        for(int i=0;i<coins.size();i++) {
            for(int j=coins[i];j<=amount;j++) {
                dp[j]+=dp[j-coins[i]];
            }
        }
        return dp[amount];
    }
};
```
