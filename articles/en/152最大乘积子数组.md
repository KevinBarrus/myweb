Given an integer array `nums`, find the non-empty contiguous subarray with the largest product and return the product corresponding to that subarray.

The answer to the test cases is a **32-bit** integer.

**Note:** The product of an array containing only one element is the value of that element.

**Example 1:**

**Input:** nums = `[2,3,-2,4]`
**Output:** `6`
**Explanation:** The subarray `[2,3]` has the maximum product, 6.

**Example 2:**

	**Input:** nums = `[-2,0,-1]`
	**Output:** 0
	**Explanation:** The result cannot be 2, because `[-2,-1]` is not a subarray.

**Constraints:**

- `1 <= nums.length <= 2 * 104`
- `-10 <= nums[i] <= 10`
- The product of any subarray of `nums` is **guaranteed** to be a **32-bit** integer.

Clearly, this can be decomposed into subproblems. For the element at index `i`, if we want the contiguous subarray ending at element `i` to have the maximum product, we want the product of a contiguous subarray ending at element `i - 1` to be minimum/maximum. If the element is negative, we want the minimum; if it is positive, we want the maximum.

Let `dp[i]` represent the product of the contiguous subarray ending at element `i`, and let `a[i]` represent the element at index `i`. We get:

If `a[i] < 0`, then `dp[i]_Max = dp[i]_Min * a[i]`.

If `a[i] > 0`, then `dp[i]_Max = dp[i]_Max * a[i]`.

If `a[i] = 0`, then `dp[i]_Max = 0`. But does `dp[i+1]` also have to be 0? Clearly not: it can form a subarray by itself.

Therefore, there is another case where we do not need to consider `dp[i-1]` at all. For example, when `dp[i-1]` is non-positive and `a[i] > 0`, `a[i]` should form a subarray independently.

Thus:

`dp[i]_Max = Max(dp[i-1]_Max * a[i], dp[i-1]_Min * a[i], a[i]`

Notice three things:
1. Since state `dp[i]` only depends on `dp[i-1]`, there is no need to allocate an array; variables can be used as a rolling array.
2. We must maintain `dp[i-1]_Max` and `dp[i-1]_Min`, recorded by two variables, `dpMax` and `dpMin`.
3. If `a[i] < 0`, then left Max corresponds to right Min in the equation, while left Max corresponds to right Max otherwise. Before calculating, we can add a branch: if `a[i] < 0`, swap `dpMax` and `dpMin`. Then the remaining code uniformly uses left Max/right Max and left Min/right Min.

When using a rolling array, remember to preserve the old values. If you calculate `dpMin` first and then `dpMax`, `dpMin` has already been updated, but `dpMax` needs the old `dpMin`, so the result is wrong. In that case, the recurrence is not `dp[i]_Max = Max(dp[i-1]_Max * a[i], dp[i-1]_Min * a[i], a[i]`, but `dp[i]_Max = Max(dp[i-1]_Max * a[i], dp[i]_Min * a[i], a[i]`.

However, after adding the `if(a[i] < 0)` branch and swapping, left Max/right Max and left Min/right Min are used uniformly. Max does not use Min, and Min does not use Max, so the problem of using an old value that has already become a new value does not occur.

```java
class Solution {
    public int maxProduct(int[] nums) {
        int ans = Integer.MIN_VALUE;
        int dpMax = 1; // initial value is 1 to make multiplication convenient
        int dpMin = 1;
        for(int a : nums) {
            // dpMin = Min(dpMin*a, dpMax*a, a)
            // dpMax = Max(dpMin*a, dpMax*a, a)
            if(a < 0) {
                // if a is negative, the original minimum dpMin multiplied by a becomes the maximum, and dpMax becomes the minimum
                // therefore, when finding dpMin, dpMax*a must be smaller than dpMin*a, so dpMin*a can be omitted; dpMax is analogous
                // swap dpMin and dpMax
                // if a is positive, dpMin*a is necessarily smaller than dpMax*a when finding dpMin
                // the swap also performs memoization, preserving the current dpMin and dpMax
                int tmp = dpMin;
                dpMin = dpMax;
                dpMax = tmp;
            }
            dpMin = Math.min(dpMin*a, a);
            dpMax = Math.max(dpMax*a, a);
            ans = Math.max(ans, dpMax);
        }
        return ans;
    }
}
```
