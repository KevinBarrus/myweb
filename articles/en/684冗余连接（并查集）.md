### 684 Redundant Connection (Union-Find)

Problem link: [684. Redundant Connection - LeetCode](https://leetcode.cn/problems/redundant-connection/description/)

A tree can be regarded as a connected and **acyclic** **undirected** graph.

Given a graph obtained by adding one edge to a tree with `n` nodes (node values `1` through `n`). The two different endpoints of the added edge have numbers between `1` and `n`, and the added edge did not already exist in the tree. The graph information is recorded in a two-dimensional array `edges` of length `n`, where `edges[i] = [ai, bi]` indicates an edge between `ai` and `bi`.

Find an edge that can be removed so that the remaining graph is a tree with `n` nodes. If there are multiple answers, return the last one that appears in the array `edges`.

**Example 1:**

![img](https://pic.leetcode-cn.com/1626676174-hOEVUL-image.png)

```
Input: edges = [[1,2], [1,3], [2,3]]
Output: [2,3]
```

**Example 2:**

![img](https://pic.leetcode-cn.com/1626676179-kGxcmu-image.png)

```
Input: edges = [[1,2], [2,3], [3,4], [1,4], [1,5]]
Output: [1,4]
```

**Constraints:**

- `n == edges.length`
- `3 <= n <= 1000`
- `edges[i].length == 2`
- `1 <= ai < bi <= edges.length`
- `ai != bi`
- There are no duplicate edges in `edges`.
- The given graph is connected.

To find the last such edge, traverse `edges` from front to back. This is equivalent to connecting these nodes one by one, so we can see which edge causes the graph to contain a cycle.

Consider Example 2:

1 -> 2 :white_check_mark:

2 -> 3 :white_check_mark:

3 -> 4 :white_check_mark:

1 -> 4 :x:

Therefore, we should remove edge 1 - 4.

Abstractly, the reason to remove 1 - 4 is that nodes 1 and 4 were already reachable from each other before we connected them. In other words, 1 and 4 were already in the same set.

This gives us the insight that if two nodes are already in the same set, connecting them again necessarily creates a cycle.

Union-Find is a common technique for determining whether two nodes belong to the same set, so use it here: traverse `edges` and determine whether the two nodes are in the same set. If they are, the answer is found; otherwise, add them to the set.

```c++
class Solution
{
public:
    int n=1005;//from the constraints, n does not exceed 1000
    vector<int>father=vector<int>(n,0);
    //initialize Union-Find
    void init()
    {
        for(size_t i=0;i<father.size();i++)
        {
            father[i]=i;//everyone has no leader or subordinate and forms a group of their own
        }
    }
    //find the root
    int find(int u)
    {
        return u==father[u]?u:father[u]=find(father[u]);
    }
    //determine whether two nodes belong to the same set
    bool same(int u,int v)
    {
        return find(u)==find(v);
    }
    //join a set
    void join(int u,int v)
    {
        if (find(u)==find(v)) return;//already in the same set
        u=find(u);
        v=find(v);
        father[v]=u;
    }
    vector<int> findRedundantConnection(vector<vector<int>>& edges)
    {
        init();
        for(auto& e:edges)
        {
            if(same(e[0],e[1]))
            {
                return {e[0],e[1]};
            }
            join(e[0],e[1]);
        }
        return {};
    }
};
```

Union-Find is relatively easy to understand. Imagine a group of people playing a game together, finding their supervisors and subordinates, and joining hands to connect them.

Initialization: at the beginning, nobody is holding hands with anyone else. This is equivalent to each person being their own leader and subordinate.

Finding the root: check whether node `u` is its own supervisor. If so, it is the highest-level leader because it has no supervisor. If not, move upward to find `u`'s immediate leader `father[u]`. The reason for setting `father[u] = find(father[u])` is to simplify the whole organizational hierarchy: while finding the root, make `u`'s immediate leader directly become `u`'s highest-level leader, so `u` can connect directly to the highest-level leader without passing through layer after layer of leaders.

Joining a set: if `u` and `v` are already in the same department, there is no need to join hands again. Otherwise, make `u` the leader of `v` and join them.
