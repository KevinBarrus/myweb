[287. Find the Duplicate Number - LeetCode](https://leetcode.cn/problems/find-the-duplicate-number/description/?envType=study-plan-v2&envId=top-100-liked)

Given an array `nums` containing `n + 1` integers, where each integer is in the range `[1, n]` inclusive, it is known that at least one integer is repeated.

Assume that `nums` contains **only one repeated integer**. Return **that repeated number**.

Your solution must not modify the array `nums` and must use only constant `O(1)` extra space.

**Example 1:**

**Input:** nums = `[1,3,4,2,2]`
**Output:** 2

**Example 2:**

**Input:** nums = `[3,1,3,4,2]`
**Output:** 3

**Example 3:**

**Input:** nums = `[3,3,3,3,3]`
**Output:** 3

**Constraints:**

- `1 <= n <= 105`
- `nums.length == n + 1`
- `1 <= nums[i] <= n`
- **Only one integer** appears **two or more times** in `nums`; every other integer appears **exactly once**.

**Follow-up:**

- How can you prove that at least one duplicate number exists in `nums`?
- Can you design a solution with linear `O(n)` time complexity?

For each `i = 0, 1, 2, ..., n`, draw a directed edge from `i` to `nums[i]`, producing a directed graph.

The in-degree of each node represents the number of times that node appears in `nums`.

Take Example 1, `[1, 3, 4, 2, 2]`, as an example.

Because 2 appears twice, at indices 3 and 4, there must be two edges, `3 -> 2` and `4 -> 2`. Therefore, the in-degree of 2 is its number of occurrences.

More rigorously, suppose `nums[i] == nums[j] == k`, meaning that `k` is the number that appears repeatedly. Then the two edges `i -> k` and `j -> k` must be created.

Since every node has an out-degree of 1 (because each index is unique), `n + 1` nodes have `n + 1` edges, so this directed graph must contain a cycle. Find the entrance to the cycle.

There may be multiple connected components. For example, in `[1, 2, 1, 4, 3]`, 3 and 4 point to each other and form a connected component. Therefore, we must start searching from node 0.

The problem is now equivalent to finding the node where a cycle begins in a linked list. Use Floyd's cycle detection algorithm, which is the fast-and-slow pointer method.

Assume it takes `a` steps from the head node to the cycle entrance, the cycle length is `b`, and the slow pointer has taken `c` steps when the pointers meet. The fast pointer has taken `2c` steps. If the fast pointer has traveled `k` more cycles than the slow pointer, then `2c - c = kb`, so `c = kb`.

Starting from the cycle entrance, the slow pointer travels `c - a = kb - a` steps within the cycle to reach the meeting point.

For the fast pointer, starting from the cycle entrance, it travels `2kb - a` steps within the cycle to reach the meeting point.

Now let both pointers move another `a` steps. Starting from the cycle entrance, the slow pointer has traveled `kb` steps within the cycle, while the fast pointer has traveled `2kb` steps. Since the cycle length is `b`, the slow pointer has traveled `k` complete cycles and the fast pointer has traveled `2k` complete cycles. Therefore, the point reached after moving `a` more steps from the meeting point is the cycle entrance.

In other words, after the meeting, let a new pointer start from the head node and let the slow pointer start from the meeting point. The node where they meet is the cycle entrance. The slow pointer is `a` steps away from the meeting point, and `a` is the number of steps from the head node to the cycle entrance.

```java
class Solution {
    public int findDuplicate(int[] nums) {
        int slow = 0, fast = 0; // 0 cannot be in the cycle because its in-degree is 0
        while(true) {
            slow = nums[slow]; // slow = slow.next
            fast = nums[nums[fast]]; // fast = fast.next.next
            if(fast == slow) {
                break;
            }
        }

        int head = 0;
        while(slow != head) {
            slow = nums[slow];
            head = nums[head];
        }
        return slow;
    }
}
```
