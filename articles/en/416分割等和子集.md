Given a **non-empty** array `nums` containing only **positive integers**, determine whether the array can be partitioned into two subsets such that the sums of the elements in both subsets are equal.

**Example 1:**

**Input:** nums = [1,5,11,5]
**Output:** true
**Explanation:** The array can be partitioned into [1, 5, 5] and [11].

**Example 2:**

**Input:** nums = [1,2,3,5]
**Output:** false
**Explanation:** The array cannot be partitioned into two subsets with equal sums.

**Constraints:**

- `1 <= nums.length <= 200`
- `1 <= nums[i] <= 100`

### Prerequisite: 0/1 Knapsack

Scenario: There are `n` items and a knapsack with capacity `bagweight`. The weight of item `i` is `weight[i]`, its value is `value[i]`, and each item can be used only once. Find the maximum total value of the items placed in the knapsack.

Brute force: each item is either selected or not selected. Use backtracking. The time complexity is `O(2^n)`.

Use dynamic programming for optimization. First clarify the dimensions and meaning of the `dp` array. Since we need to consider both the items and their weights, start with a two-dimensional array. In `dp[i][j]`, `i` represents the item index, `j` represents the knapsack capacity, and `dp[i][j]` represents the maximum total value obtainable by selecting any items from indices 0 through `i` with a knapsack of capacity `j`.

Next, determine the recurrence.

Take `dp[2][3]` as an example. It means: using a knapsack of capacity 3, select any items among items 0, 1, and 2 to obtain the maximum total value. There are two cases: put item 2 in the knapsack, or do not put item 2 in it.

If item 2 is not placed, whether item 2 exists has no effect, so `dp[2][3] = dp[1][3]`.

If item 2 is placed, enough space must be reserved for it.

If the weight of item 2 is greater than 3, it cannot be placed in the knapsack. If it is not greater than 3, suppose its weight is 2. For a knapsack of capacity 3, 1 unit of capacity remains after placing item 2, so we only need to check the maximum total value obtainable by selecting items 0 and 1 in a knapsack of capacity 1. Then `dp[2][3] = dp[1][1] + value[2]`.

Abstractly, calculating `dp[i][j]` has these cases:

Do not place item `i`: item `i` has no effect, so `dp[i][j] = dp[i-1][j]`.

Place item `i`: reserve space for it. Before placing item `i`, the knapsack capacity is `j-weight[i]`, so `dp[i][j] = dp[i-1][j-weight[i]] + value[i]`.

Take the maximum of the two.

Then initialize the `dp` array (because `i` is derived from `i-1`, initialization is required):

`dp[i][0]`: the knapsack capacity is 0, so no item can be placed and the value is initialized to 0.

`dp[0][j]`: only item 0 can be selected. If `j` is smaller than `weight[0]`, do not select it because the capacity is insufficient, and initialize the value to 0; otherwise initialize it to `value[0]`.

From the recurrence, all other indices can be derived from values in the upper-left area, so the remaining elements can simply be initialized to 0.

Thus, initialization only needs to process the zeroth row; all other positions are initialized to 0.

Now consider the traversal order of the `dp` array.

Should we traverse items first or the knapsack first? Either is possible, because the result is derived either from directly above or from the upper left.

Traversing items first and then the knapsack is equivalent to fixing the columns and filling the table row by row.

Conversely, traversing the knapsack first and then the items is equivalent to fixing the rows and filling the table column by column.

#### Rolling Array

The two-dimensional recurrence shows that `dp[i][j]` only relates to `dp[i-1][j]` and `dp[i-1][j-weight[i]]`. The previous row, `i-1`, can be copied through a rolling array, so we can optimize it to a one-dimensional array.

The optimized recurrence is `dp[j] = max(dp[j-weight[i]]+value[i], dp[j])`.

The `dp[j]` inside the parentheses is the `dp[j]` from the previous row, equivalent to `dp[i-1][j]`.

Next, initialize this one-dimensional array.

`dp[j]` represents the maximum total value that a knapsack of capacity `j` can hold. Thus `dp[0] = 0`, and all other positions are derived from earlier positions, so every position only needs to be initialized to 0.

Now consider the traversal order: **the correct approach is to traverse items first and then traverse the knapsack capacity in reverse order**.

First, why traverse in reverse order?

If we traverse in forward order, the same item may be placed multiple times. Because we use a rolling array, every update of the `dp` array checks whether item `i` should be placed in the knapsack. If an earlier capacity has already included item `i`, checking whether to include item `i` again at a later position is meaningless. Reverse traversal avoids this problem because `dp[j]` depends on earlier elements.

For example: `weight[0] = 1`, `value[0] = 20`.

With forward traversal, in the first round:

`dp[1] = dp[1-weight[0]] + value[0] = 20`

`dp[2] = dp[2-weight[0]] + value[0] = 40`

But `dp[2]` means the maximum value that can be held in a capacity-2 knapsack when selecting item 0. Clearly, item 0 can only be selected once, so the maximum value should be 20. It becomes 40 because it was counted an extra time.

With reverse traversal, we truly use `dp[i-1][j-weight[i]]`, because we need the value from the previous row and must not overwrite it first.

Second, why traverse items before the knapsack capacity?

If we traverse the knapsack capacity first and then the items, the code should be:

```c++
for(int j=bagweight;j>=1;j--) {
    for(int i=0;i<weight.size();i++) {
        if(j>=weight[i]) dp[j]=max(dp[j],dp[j-weight[i]]+value[i]);
    }
}
```

Suppose `bagweight=5`, there are three items with weights 1, 2, and 3 and values 1, 2, and 3.

Initially, `j=5`, and we enter the inner loop:

`i=0`, `j >= weight[0] = 1`, so `dp[5] = dp[5-1] + value[0] = 0 + 1 = 1`.

`i=1`, `j >= weight[1] = 2`, so `dp[5] = max(dp[5], dp[5-2] + 2) = 2`.

At this point, we see the problem: a capacity-5 knapsack can contain both items with weights 1 and 2, so the total value should be 3, but when `i=1` it is only 2.

If we traverse items first and then the knapsack capacity:

```c++
for(int i=0;i<weight.size();i++) {
    for(int j=bagweight;j>=weight[i];j--) {
        dp[j]=max(dp[j],dp[j-weight[i]]+value[i]);
    }
}
```

Again suppose `bagweight=5`, with three items of weights 1, 2, and 3 and values 1, 2, and 3.

In the first round, `i=0`, and we enter the inner loop.

`j=5`, `dp[5] = dp[4] + 1 = 1`.

`j=4`, `dp[4] = dp[3] + 1 = 1`.

And so on. Except for `dp[0] = 0`, all other values are 1 in this round, because only item 0 can be selected, and selecting it is better than not selecting it.

In the second round, `i=1`, and we enter the inner loop.

`j=5`, `dp[5] = max(1, dp[3] + 2) = 3`.

Now the knapsack truly contains item 0 and item 1.

Abstractly, because reverse traversal is required, if we traverse the knapsack capacity first and then the items, the earlier capacities have not yet been processed, so each iteration can effectively place only one item.

Therefore, items must be traversed before the knapsack capacity.

### Return to the Problem

The problem is equivalent to asking whether there is a subsequence whose sum is half the sum of all array elements.

In other words, first calculate the array sum `sum`, then determine whether a subsequence exists whose sum is `sum/2`.

This is equivalent to having a knapsack with capacity `sum/2` and asking whether some set of items can fill it completely.

Here, the numbers are the items, and both the value and weight of an item are its numeric value.

Therefore, we still calculate the maximum value the knapsack can hold, then check whether the maximum value equals the knapsack capacity.

Based on the 0/1 knapsack knowledge above:
- `dp[j]` represents the maximum value that a knapsack of capacity `j` can hold.
- `dp[0] = 0`.
- The outer loop traverses items, and the inner loop traverses knapsack capacity.
- The knapsack capacity must be traversed in reverse order.

Java

```java
class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for(int num : nums) {
            sum += num;
        }
        if(sum % 2 == 1) {
            return false;
        }

        int target = sum / 2;

        int[] dp = new int[10005]; // each element is at most 100, there are at most 200, and sum/2 is at most 10000, so use size 10005

        // traverse items in the outer loop and knapsack capacity in reverse in the inner loop
        for(int i = 0; i < nums.length; i++) {
            for(int j = target; j >= nums[i]; j--) {
                dp[j] = Math.max(dp[j], dp[j - nums[i]] + nums[i]);
            }
        }

        return dp[target] == target;
    }
}
```

Python

```python
class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        n = len(nums)
        if n < 2 :
            return False

        total = sum(nums)
        if total % 2 == 1 :
            return False

        target = total // 2

        dp = [0 for _ in range(10005)]

        for i, num in enumerate(nums) :
            for j in range(target, num - 1, -1) :
                dp[j] = max(dp[j], dp[j - num] + num)

        return dp[target] == target
```
