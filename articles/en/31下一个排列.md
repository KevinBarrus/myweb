A **permutation** of an integer array is an arrangement of all its members in a sequence or linear order.

- For example, for `arr = [1,2,3]`, `[1,2,3]`, `[1,3,2]`, `[3,1,2]`, and `[2,3,1]` can all be regarded as permutations of `arr`.

The **next permutation** of an integer array is the next lexicographically greater permutation of its integers. More formally, if all permutations of an array are arranged in a container in lexicographic order from small to large, the **next permutation** of the array is the permutation immediately after it in that ordered container. If there is no next greater permutation, the array must be rearranged into the lexicographically smallest permutation, meaning its elements are arranged in ascending order.

- For example, the next permutation of `arr = [1,2,3]` is `[1,3,2]`.
- Similarly, the next permutation of `arr = [2,3,1]` is `[3,1,2]`.
- The next permutation of `arr = [3,2,1]` is `[1,2,3]`, because `[3,2,1]` has no lexicographically greater permutation.

Given an integer array `nums`, find the next permutation of `nums`.

You must modify it **[in place](https://baike.baidu.com/item/%E5%8E%9F%E5%9C%B0%E7%AE%97%E6%B3%95)** and use only constant extra space.

**Example 1:**

**Input:** nums = `[1,2,3]`
**Output:** `[1,3,2]`

**Example 2:**

**Input:** nums = `[3,2,1]`
**Output:** `[1,2,3]`

**Example 3:**

**Input:** nums = `[1,1,5]`
**Output:** `[1,5,1]`

**Constraints:**

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

This is similar to calculating the next integer. For example, if the three digits of 123 are randomly permuted, the integer closest to and greater than 123 is 132. The same applies to 115: the next one is 151.

Why can we state the result immediately? Looking back at our reasoning process may help us find a solution.

Take `1 2 5 4 3` as an example. Its next permutation is `1 3 2 4 5`. First, why do we need to change 2? Because there is a number greater than 2 to its right. Second, why swap 2 and 3? To follow lexicographic order, the element to swap should be the smallest number greater than 2. After the swap, we get `1 3 5 4 2`. Notice that the lexicographic order of `5 4 2` is not the smallest, so it must be adjusted to `2 4 5`.

Therefore, in the first step, we need to find the first number `x` from right to left that can be increased, meaning there is a number greater than `x` to its right. In the example, `x` is 2. Clearly, the sequence to the right of `x` is monotonically decreasing; otherwise, the first number that can be increased would necessarily be to the right of `x`. Thus, the first step is equivalent to finding, from right to left, the first number `x` that is smaller than its adjacent number on the right.

The second step is to determine which number to swap with. Since the next permutation is defined by lexicographic order, the element to swap should be the smallest number greater than `x` on its right. The sequence to the right of `x` is known to be decreasing, so traverse it from right to left again. The first number `y` greater than `x` is the one to swap with `x`.

The third step is the swap.

In the fourth step, after the swap, the sequence to the right of `y` must be decreasing. All elements to the right of `x` are greater than `x`, and `y` is the smallest number greater than `x`. In other words, all numbers between `x` and `y` are greater than both of them. After the swap, the only number to the right of `y` that is smaller than it is `x`; because the sequence was already decreasing before the swap, replacing the smallest element with an even smaller one keeps it decreasing. We need to change it to increasing order so that the lexicographic order is the smallest possible greater order, so we simply reverse the sequence on the right.

The four steps for the usual case are now clear. Next, consider the special case.

If the current sequence is already the lexicographically largest, the next permutation should be the lexicographically smallest one according to the rule. How should we handle it?

In fact, if the sequence is lexicographically largest, it must be monotonically decreasing, while the lexicographically smallest sequence must be monotonically increasing. Therefore, we only need to reverse the sequence.

Java
```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;

        // 1. Find the first number smaller than its adjacent number on the right, from right to left
        int i = n - 2;
        while(i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }

        // If it is found, perform the second step; otherwise reverse the entire sequence directly
        if(i >= 0) {
            // 2. Find the first number greater than nums[i], from right to left
            int j = n - 1;
            while(nums[j] <= nums[i]) {
                j--;
            }
            // As analyzed above, j must be found; swap them
            int tmp = nums[i];
            nums[i] = nums[j];
            nums[j] = tmp;
        }

        // 3. Reverse [i + 1, n - 1]. If step two was skipped, i + 1 = 0, which is valid
        int left = i + 1;
        int right = n - 1;
        while(left < right) {
            int tmp = nums[left];
            nums[left] = nums[right];
            nums[right] = tmp;
            left++;
            right--;
        }
    }
}
```
