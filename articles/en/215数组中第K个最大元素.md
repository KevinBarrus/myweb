[215. Kth Largest Element in an Array - LeetCode](https://leetcode.cn/problems/kth-largest-element-in-an-array/description/?envType=study-plan-v2&envId=top-100-liked)

Given an integer array `nums` and an integer `k`, return the **kth** largest element in the array.

Note that you need to find the kth largest element after sorting the array, not the kth distinct element.

You must design and implement an algorithm with `O(n)` time complexity to solve this problem.

**Example 1:**

**Input:** `[3,2,1,5,6,4]`, k = 2
**Output:** 5

**Example 2:**

**Input:** `[3,2,3,1,2,4,5,5,6]`, k = 4
**Output:** 4

**Constraints:**

- `1 <= k <= nums.length <= 105`
- `-104 <= nums[i] <= 104`

The kth largest element has index `n - k` in a sorted array, so this problem becomes: randomly choose a number, put it in the position where it should be, and return it if this position is exactly `n - k`.

Since this number, called the `pivot`, is already in its correct position, all numbers to its left must be smaller than it, and all numbers to its right must be larger than it. They are not necessarily sorted, but the pivot is indeed in the position where it should be. If this position is greater than `n - k`, the element at index `n - k` must be to the left of the pivot. Since the kth largest element has index `n - k` in the ascending array and the pivot is to its right, the desired element is clearly to the left of the pivot, because all elements on the left are smaller than it. We can therefore randomly select a number in the left subarray and put it in the position where it should be. If the pivot's position is smaller than `n - k`, search in the right subarray.

Temporarily call the operation “select a random number within an interval and put it in the position where it should be in that interval” `prp` (Put it to the Right Place). Since we need to compare the pivot's position with `n - k`, we can determine that the return value of `prp` should be the pivot's index. We can also write the flow of `findKthLargest`:

```python
    def findKthLargest(self, nums: List[int], k: int) -> int:
        n = len(nums)
        target_index = n - k
        left, right = 0, n - 1
        while True:
            i = self.prp(nums, left, right)
            if i == target_index:
                # found the kth largest element
                return nums[i]
            elif i < target_index:
                # the pivot is at the correct index, but this index is still smaller than n - k
                # all elements to the right of the pivot are larger, and n - k is to the right of the pivot
                # so the kth largest element must be larger than the pivot; search in the right subarray
                left = i + 1
            else:
                right = i - 1
```

Next, complete the `prp` function.

1. Select a random number as the pivot from `[left, right]`, with index `i`.
2. Swap `nums[i]` and `nums[left]`. Our goal is to put numbers smaller than the pivot to its left and numbers larger than the pivot to its right within `[left, right]`, so we only need to record the pivot's value. Move the pivot out of the part of the array to process, so we do not need to handle the pivot separately when traversing this part.
3. After the swap, `pivot == left`, and the pivot has been moved away from the working area. Set `i = left + 1` and `j = right`; `[i, j]` is the part to traverse and process. Enter the loop:

(a) If `i` is not to the right of `j` and `nums[i]` is smaller than the pivot, move `i` one position to the right. We want numbers smaller than the pivot on its left. Otherwise, do not move it. The comparison is strictly smaller to avoid degenerating to `O(n^2)` when all array elements are equal.

(b) If `i` is not to the right of `j` and `nums[j]` is larger than the pivot, move `j` one position to the left, for the same reason.

Why is one condition “`i` is not to the right of `j`” instead of “`i` is to the left of `j`”? In other words, why can `i == j` still be necessary for continued movement? Suppose `i` stops before meeting `j`. Why does `i` stop? Because `nums[i] > pivot`. If `j` moves to `i`, then `j == i`, and the loop is not entered. At this point, index `j` is the correct position of the pivot in `[left + 1, right]`. But if we swap `nums[left]` and `nums[j]`, since `j` and `i` overlap, the reason `i` stopped is that `nums[i]` is greater than the pivot. Therefore, `nums[j]` is greater than the pivot, which means we have moved a number greater than the pivot to its left. This is clearly incorrect.

Can we swap `nums[left]` and `nums[j - 1]`? That is not suitable, because if both `left` and `right` are 0, then `j - 1` is out of bounds.

Therefore, we should return `j`, and the common condition of the two loops in (a) and (b) should be `i <= j`, not `i < j`.

(c) After `i` and `j` finish exploring, if they overlap or `i` has moved to the right of `j`, break. Every element to the right of `j` is necessarily larger than the pivot, and every element to the left of `i` is necessarily smaller than the pivot. When they overlap or `j` is to the left of `i`, the pivot's correct position has been determined.

(d) If both `i` and `j` stop before meeting, then `nums[i] > pivot` and `nums[j] < pivot`, but `i` is already to the right of `j`. A number on the left is larger than a number on the right, which is not what we want. Therefore, swap `nums[i]` and `nums[j]`, then process `[i + 1, j - 1]` in the next iteration. At this point, `i` and all elements to its left are smaller than the pivot, and `j` and all elements to its right are larger than the pivot. Being smaller than the pivot drives `i` forward, and being larger than the pivot drives `j` backward. Moving `i` and `j` closer lets all elements larger than the pivot in `[i + 1, j - 1]` move right and all elements smaller than the pivot move left.

(e) After the loop ends, swap `nums[left]` and `nums[j]`; the reason was explained above.

(f) Return `j`; index `j` is the position where the pivot should be.

There is another reason why the condition cannot be `i < j`. See the example given by Ling Shen:

Consider `nums = [2,1,3]` and `pivot = 2`. The left pointer `i = 1` moves to `i = 2`, while the right pointer `j = 2` cannot move because `i < j` is not satisfied. We then swap 2 and `nums[j] = 3`, obtaining `[3,1,2]`, and return `j = 2`. However, there is an element greater than `pivot = 2` to the left of `j = 2`, so the partition fails.

If we write `i <= j`, then finally `i = 2` and `j = 1`. We swap 2 and `nums[j] = 1`, obtaining `[1,2,3]`, and return `j = 1`. This partition is correct.

```python
class Solution:
    def prp(self, nums: List[int], left: int, right: int) -> int:
        i = randint(left, right)
        pivot = nums[i]
        nums[i], nums[left] = nums[left], nums[i]
        i, j = left + 1, right
        while True:
            while i <= j and nums[i] < pivot:
                i += 1
            while i <= j and nums[j] > pivot:
                j -= 1

            if i >= j:
                break

            nums[i], nums[j] = nums[j], nums[i]
            j -= 1
            i += 1

        nums[left], nums[j] = nums[j], nums[left]
        return j

    def findKthLargest(self, nums: List[int], k: int) -> int:
        n = len(nums)
        target_index = n - k
        left, right = 0, n - 1
        while True:
            i = self.prp(nums, left, right)
            if i == target_index:
                # found the kth largest element
                return nums[i]
            elif i < target_index:
                # the pivot is at the correct index, but this index is still smaller than n - k
                # all elements to the right of the pivot are larger, and n - k is to the right of the pivot
                # so the kth largest element must be larger than the pivot; search in the right subarray
                left = i + 1
            else:
                right = i - 1
```

Let us analyze the time complexity.

During the first call to `prp`, `n - 1` numbers, excluding the pivot, are traversed, so the complexity is `n` (let the array length be `n`).

After the first call, we choose either the left or the right side, so the recurrence is:

$$
T(n) = T(\frac n 2) + n
$$

If both sides were recursive, it would become:

$$
T(n) = 2T(\frac n 2) + n
$$

Expand $$ T(\frac n 2)$$:

$$
T(n) = T(\frac n 4) + \frac n 2 + n
$$

Expanding further:

$$
T(n) = T(\frac n 8) + \frac n 4 + \frac n 2 + n
$$

Finally:

$$
T(n) = \lim_{k \to +\infty} [T(\frac {n} {2^k}) + \sum_{i=0}^{k-1} {\frac {n} {2^{i}}}]
$$

That is:

$$
T(n) = \lim_{k \to +\infty} \sum_{i=0}^{k} {\frac {n} {2^{i}}}
$$

And:
$$
\sum_{i=0}^{k} {\frac {n} {2^{i}}} = n[2-{(\frac 1 2)^{k}}]
$$

Therefore:
$$
T(n) = 2n
$$

So the time complexity is `O(n)`.
