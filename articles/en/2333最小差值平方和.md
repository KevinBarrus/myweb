Problem link: [2333. Minimum Sum of Squared Difference - LeetCode](https://leetcode.cn/problems/minimum-sum-of-squared-difference/)

You are given two integer arrays `nums1` and `nums2`, both 0-indexed and of length `n`.

The **sum of squared differences** between `nums1` and `nums2` is defined as the sum of `(nums1[i] - nums2[i])2` for all `0 <= i < n`.

You are also given two positive integers `k1` and `k2`. You can add or subtract 1 from any element in `nums1` at most `k1` times. Similarly, you can add or subtract 1 from any element in `nums2` at most `k2` times.

Return the minimum **sum of squared differences** after modifying `nums1` at most `k1` times and `nums2` at most `k2` times.

**Note:** You may turn elements in the arrays into negative integers.

**Example 1:**

```
Input: nums1 = [1,2,3,4], nums2 = [2,10,20,19], k1 = 0, k2 = 0
Output: 579
Explanation: The elements in nums1 and nums2 cannot be modified because k1 = 0 and k2 = 0.
The sum of squared differences is: (1 - 2)2 + (2 - 10)2 + (3 - 20)2 + (4 - 19)2 = 579.
```

**Example 2:**

```
Input: nums1 = [1,4,10,12], nums2 = [5,8,6,9], k1 = 1, k2 = 1
Output: 43
Explanation: One way to obtain the minimum sum of squared differences is:
- Increase nums1[0] once.
- Increase nums2[2] once.
The minimum sum of squared differences is:
(2 - 5)2 + (4 - 8)2 + (10 - 7)2 + (12 - 9)2 = 43.
Note that other ways can also obtain the minimum sum of squared differences, but no solution obtains an answer smaller than 43.
```

**Constraints:**

- `n == nums1.length == nums2.length`
- `1 <= n <= 105`
- `0 <= nums1[i], nums2[i] <= 105`
- `0 <= k1, k2 <= 109`

The idea is not difficult: first calculate the difference at each position, then reduce the differences as much as possible.

The first time, I got stuck halfway through:

```c++
class Solution {
public:
    long long minSumSquareDiff(vector<int>& nums1, vector<int>& nums2, int k1, int k2) {
        int n=nums1.size();
        long long ans=0;
        vector<int>gap(n);
        for(int i=0;i<n;i++) {
            gap.push_back(abs(nums1[i]-nums2[i]));
        }
        sort(gap.begin(),gap.end());
    }
};
```

After sorting the `gap` array, how should we handle the two `k` values? Can setting the largest difference to 0 directly guarantee the minimum?

However, we know that reducing the differences in the `gap` array as much as possible is valid. Therefore, let `gap[i]` record the number of times difference `i + 1` appears. Then let `k = k1 + k2` (since we only calculate the difference, it no longer matters which `k` acts on which array), and use `k` to reduce the number of occurrences of the largest values until `k is exhausted`.

```c++
class Solution {
public:
    long long minSumSquareDiff(vector<int>& nums1, vector<int>& nums2, int k1, int k2) {
        vector<int>gap(1e5+5,0);//because array elements are in [0,1e5]
        int n=nums1.size();
        for(int i=0;i<n;i++) {
            gap[abs(nums1[i]-nums2[i])]++;
        }
        int k=k1+k2;
        for(int i=gap.size()-1;k>0&&i>0;i--) {
            int change=min(k,gap[i]);//amount to reduce
            k-=change;//consume k
            gap[i-1]+=change;
            gap[i]-=change;
        }
        long long ans=0;
        for(long long i=0;i<gap.size();i++) {
            if(gap[i]) {
                ans+=(i*i*gap[i]);
            }
        }
        return ans;
    }
};
```

Explanation: suppose the differences are `[1,2,2,3]` and `k=4`. Then `gap[1]=1`, `gap[2]=2`, and `gap[3]=1`.

Starting from the last element, `change=1`, so consume 1 unit and change the pair whose difference is 3 into a pair whose difference is 2. Therefore, increase `gap[2]` by one, decrease `gap[3]` by one, and decrease `k` by one. In other words, our greedy strategy is to reduce the number of occurrences of large differences as much as possible.
