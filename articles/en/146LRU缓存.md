Problem link: [146. LRU Cache - LeetCode](https://leetcode.cn/problems/lru-cache/?envType=study-plan-v2&envId=top-100-liked)

Design and implement a data structure that satisfies the constraints of [LRU (Least Recently Used) Cache](https://baike.baidu.com/item/LRU).

Implement the `LRUCache` class:

- `LRUCache(int capacity)` initializes the LRU cache with **positive integer** capacity `capacity`.
- `int get(int key)` returns the value of the key if `key` exists in the cache; otherwise, it returns `-1`.
- `void put(int key, int value)` updates the data value `value` if `key` already exists; otherwise, it inserts the `key-value` pair into the cache. If the insertion causes the number of keys to exceed `capacity`, the least recently used key should be **evicted**.

The functions `get` and `put` must run in an average time complexity of `O(1)`.

**Example:**

```
Input
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
Output
[null, null, null, 1, null, -1, null, -1, 3, 4]

Explanation
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // The cache is {1=1}
lRUCache.put(2, 2); // The cache is {1=1, 2=2}
lRUCache.get(1);    // Returns 1
lRUCache.put(3, 3); // This operation invalidates key 2; the cache is {1=1, 3=3}
lRUCache.get(2);    // Returns -1 (not found)
lRUCache.put(4, 4); // This operation invalidates key 1; the cache is {4=4, 3=3}
lRUCache.get(1);    // Returns -1 (not found)
lRUCache.get(3);    // Returns 3
lRUCache.get(4);    // Returns 4
```

**Constraints:**

- `1 <= capacity <= 3000`
- `0 <= key <= 10000`
- `0 <= value <= 105`
- At most `2 * 105` calls to `get` and `put`

Translate this into an analogy: you stack books on a desk, and each book has its own number. You can stack at most `capacity` books. The `get` function lets you find a book directly by its number; after finding it, place it on the top of the stack. The `put` function first checks whether the book with number `key` exists. If it does not exist, put a book on the top of the stack; if it exists, replace the original book with number `key`, and then put it on the top of the stack. If the stack is full, the book at the bottom must be removed first.

Both the `put` and `get` functions must be implemented with time complexity `O(1)`.

At first, I wanted to use a vector directly: preallocate `capacity` spaces, with every element initialized to `-1` (because the problem says that `value` is non-negative). The `get` function could obtain an element directly by index, but a problem arises: how do we move the book obtained by `get` to the top? In other words, how do we know where the last element that is not `-1` is? We can only search by traversal. Then the time complexity is not `O(1)`, but `O(n)`.

Clearly, the problem is that space was preallocated.

Then can we simply avoid preallocating space and use a variable to record the current number of elements in the vector? In this way, every element in the vector is valid. But another problem arises: if we move an element in the middle to the top, we need to fill the position that was freed, which necessarily requires moving elements, so the time complexity is definitely not `O(n)`.

Clearly, the problem is that deleting an element requires filling its position.

Therefore, a vector is definitely not suitable, let alone a queue or a stack. Based on the previous two problems, we can naturally think of a linked list. Deleting an element from a linked list is an `O(1)` operation; it does not require filling a position, and there is no preallocation problem.

After deciding to use a linked list, continue the analysis:

The `get` function first needs to solve the problem of finding the value by `key`, so there must be a hash table to maintain the key-value pairs. Next, the element corresponding to this `key` must be moved to the front of the linked list. In other words, in addition to finding the value by the key, we also need to find the node corresponding to that key. This means that the value in the hash table should be a node pointer rather than an `int`; otherwise, we cannot move the node. After finding the corresponding node, we need to move it to the front. This means that we need to know the pointer to the second node, which is somewhat troublesome because the second node may change. Therefore, we may as well create a dummy head node. Then moving a node to the head is equivalent to moving it to the position immediately after the dummy head node.

The `put` function first determines whether `key` exists; the hash table can answer this directly. If `key` exists, simply change `value`. This is where the benefit of using a node pointer as the value appears. If the value were only an `int`, there would be no way to change the value of the node in the linked list. Then we move this node to the head of the linked list. We can see that moving a node to the head is used multiple times, so it can be encapsulated as a separate function. If `key` does not exist, we create a node with `new` and put it at the front. If the size of the hash table is already greater than `capacity`, remove the last node from both the linked list and the hash table. We can also encapsulate the deletion operation as a separate function.

Now a new problem arises: how do we know the `key` of the last node? Without the key, there is no way to remove it from the hash table. Would a circular linked list work? No, because we only know that the `next` of the last node is the dummy head node. Therefore, we must use a doubly linked list. Each node must store `key` / `value` / `next` / `prev`, because after finding the tail node, we must return its `key` so that it can be removed from the hash table.

In addition, the operation of finding the node corresponding to a key can be encapsulated as a function. In this function, if the node is found, move it to the head.

```cpp
struct Node {
    int key;
    int value;
    Node* prev;
    Node* next;

    Node(int k = 0,int v = 0):key(k),value(v),prev(nullptr),next(nullptr){}
};

class LRUCache {
private:
    int cap;//capacity
    Node* dummy_head;
    unordered_map<int, Node*>mp;

    //move to the front
    void move_to_front(Node* node) {
        node->prev = dummy_head;
        node->next = dummy_head->next;//the first node added is the last node
        node->prev->next = node;
        node->next->prev = node;
    }

    //delete a node
    void del_node(Node* node) {
        node->prev->next = node->next;
        node->next->prev = node->prev;
    }

    //get the node corresponding to key and move it to the front
    Node* get_node(int key) {
        auto it = mp.find(key);
        if (it == mp.end()) {
            //the book does not exist
            return nullptr;
        }
        Node* node = it->second;
        del_node(node);//Remove the book first; otherwise, if there are only dummy_head and another node node1, node1 would point to itself
        move_to_front(node);
        return node;
    }

public:
    LRUCache(int capacity) {
        cap = capacity;
        dummy_head = new Node();
        dummy_head->next = dummy_head;
        dummy_head->prev = dummy_head;
    }

    int get(int key) {
        Node* node = get_node(key);
        return node ? node->value : -1;
    }

    void put(int key, int value) {
        Node* node = get_node(key);
        if (node) {
            //the node exists, so only update its value
            node->value = value;
            return;
        }
        //if the node does not exist, create one with new and put it at the top
        node = new Node(key, value);
        mp[key] = node;
        move_to_front(node);

        //if the capacity is exceeded, delete the last node
        if (mp.size() > cap) {
            Node* del = dummy_head->prev;
            mp.erase(del->key);
            del_node(del);
            delete del;
        }
    }
};
```
