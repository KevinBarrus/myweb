[153. Find Minimum in Rotated Sorted Array - LeetCode](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/description/?envType=study-plan-v2&envId=top-100-liked)

Given an array of length `n` that was originally sorted in ascending order, the input array is obtained after **rotating** it between `1` and `n` times. For example, the original array `nums = [0,1,2,4,5,6,7]` may become:

- After 4 rotations: `[4,5,6,7,0,1,2]`
- After 7 rotations: `[0,1,2,4,5,6,7]`

Note that the result of rotating the array `[a[0], a[1], a[2], ..., a[n-1]]` **once** is `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`.

Given an array `nums` whose element values are **distinct**, which was originally sorted in ascending order and rotated multiple times as described above, find and return the **minimum element** in the array.

You must design an algorithm with time complexity `O(log n)` to solve this problem.

**Example 1:**

**Input:** nums = [3,4,5,1,2]
**Output:** 1
**Explanation:** The original array was [1,2,3,4,5], and rotating it 3 times produced the input array.

**Example 2:**

**Input:** nums = [4,5,6,7,0,1,2]
**Output:** 0
**Explanation:** The original array was [0,1,2,4,5,6,7], and rotating it 4 times produced the input array.

**Example 3:**

**Input:** nums = [11,13,15,17]
**Output:** 11
**Explanation:** The original array was [11,13,15,17], and rotating it 4 times produced the input array.

**Constraints:**

- `n == nums.length`
- `1 <= n <= 5000`
- `-5000 <= nums[i] <= 5000`
- All integers in `nums` are **distinct**
- `nums` was originally sorted in ascending order and rotated `1` to `n` times

Following the approach from Search in Rotated Sorted Array: [LeetCode 33 - Search in Rotated Sorted Array - Zhihu](https://zhuanlan.zhihu.com/p/2067960456073974079)

Choose any number `x` and compare it with the last element of the array:
- If `x > nums[-1]`, then `nums` must be divided into two increasing segments. Every element in the first segment is greater than every element in the second segment, so the minimum must be to the right of `x`.
- Otherwise, `x` may be the minimum, or `x` may be to the right of the minimum.

Maintain the interval `(left, right]`, open on the left and closed on the right.

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = -1, len(nums) - 1
        while left + 1 < right:
            mid = (left + right) // 2
            x = nums[mid]
            if x > nums[-1]:
                left = mid
            else:
                right = mid
        return nums[right]
```

Because the interval is open on the left and closed on the right, the branch uses `left = mid` rather than `left = mid + 1`.

Because `x` may be the minimum in the `else` branch, it cannot use `right = mid - 1`; it must use `right = mid`.
