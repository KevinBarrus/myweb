Given the head of a linked list `head`, reverse the nodes of the list `k` at a time and return the modified list.

`k` is a positive integer less than or equal to the length of the linked list. If the total number of nodes is not a multiple of `k`, keep the remaining nodes in their original order.

You cannot simply change the values inside the nodes; you must actually exchange the nodes.

**Example 1:**

![](https://assets.leetcode.com/uploads/2020/10/03/reverse_ex1.jpg)

**Input:** head = `[1,2,3,4,5]`, k = 2
**Output:** `[2,1,4,3,5]`

**Example 2:**

![](https://assets.leetcode.com/uploads/2020/10/03/reverse_ex2.jpg)

**Input:** head = `[1,2,3,4,5]`, k = 3
**Output:** `[3,2,1,4,5]`

**Constraints:**

- The number of nodes in the linked list is `n`.
- `1 <= k <= n <= 5000`
- `0 <= Node.val <= 1000`

Follow-up: Can you solve this problem using `O(1)` extra memory?

### Method 1: Recursion

This is still a linked-list reversal problem, except that the number of nodes to reverse becomes `k`; we only need to add a counting variable.

For reversal, take `A -> B -> C` as an example:

```
pre   cur
A  ->  B   ->  C
head
```

Reverse in two steps:

`B - A - C`

`C - B - A`

In the first step, move the node corresponding to `cur` to the head.

If we move `pre` and `cur` one node forward, after the first step `pre` points to A and `cur` points to C.

In the second step, again move the node corresponding to `cur` to the head.

After the second step, `cur` is null and the reversal is complete.

Reversal code:

Java
```java
        ListNode pre = head;
        ListNode cur = head.next;
        while(cur != null) {
            // A -> B -> C; in the first round, pre is A and cur is B
            pre.next = cur.next; // A -> C
            cur.next = head; // B -> A; move cur to the head, so head is no longer the head and must be adjusted
            // the order is now B -> A -> C; adjust pre, cur, and head
            head = cur; // keep head as the head, so later cur nodes can be moved before it
            cur = pre.next;
        }
```

Now reverse only `k` nodes by adding a counting variable.

```java
        ListNode pre = head;
        ListNode cur = head.next;
        int cnt = 0;
        while(++cnt < k && cur != null) {
            // for k nodes, only k-1 nodes need to be moved forward, so use ++cnt rather than cnt++
            // A -> B -> C; in the first round, pre is A and cur is B
            pre.next = cur.next; // A -> C
            cur.next = head; // B -> A; move cur to the head, so head must be adjusted
            // the order is now B -> A -> C; adjust pre, cur, and head
            head = cur; // keep head as the head, so later cur nodes can be moved before it
            cur = pre.next;
        }
```

There are multiple groups, so one round is not enough. For one group, after reversal `pre` is the last node in the group and `cur` is the node after the last node. Therefore, for the next group, `cur` is its `head`, and we can call recursively.

However, pay attention to the connections between groups. After the next group is reversed, the last node of the previous group should point to the head of the next group. After each group is reversed, its tail is `pre` and its head is `head`, so the final return value should be the head `head` of this group.

What if the final group contains fewer than `k` nodes?

First, how do we determine the number of nodes? We can know it through `cnt`, which increases while reversing. This means that regardless of whether the group contains fewer than `k` nodes, reversal is unavoidable.

Therefore, reverse first and then check whether `cnt` is less than `k`. If it is, reverse once more. This is where the role of `head` becomes clear: for a group, `head` is always the head of that group.

Java

```java
/**
 * Definition for singly-linked list.
 * public class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode() {}
 *     ListNode(int val) { this.val = val; }
 *     ListNode(int val, ListNode next) { this.val = val; this.next = next; }
 * }
 */
class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        if(head == null) return null;
        ListNode pre = head;
        ListNode cur = head.next;
        int cnt = 0; // number of nodes from the k nodes already moved forward
        while(++cnt < k && cur != null) {
            // for k nodes, only k-1 nodes need to be moved forward, so use ++cnt rather than cnt++
            // A -> B -> C; in the first round, pre is A and cur is B
            pre.next = cur.next; // A -> C
            cur.next = head; // B -> A; move cur to the head, so head must be adjusted
            // the order is now B -> A -> C; adjust pre, cur, and head
            head = cur; // keep head as the head, so later cur nodes can be moved before it
            cur = pre.next;
        }
        if(cnt < k) {
            // reverse once more
            return reverseKGroup(head, cnt); // head is always the head of this group
        }
        pre.next = reverseKGroup(cur, k); // the tail of the previous group should point to the reversed head of the next group
        return head;
    }
}
```

Time complexity: there are `n/k` groups, and each group moves `k-1` nodes, so the time complexity is `O(n)`.

Space complexity: the recursion depth is `n/k`, and each level uses `O(1)` space, so the space complexity is `O(n/k)`.

### Method 2: Iteration

The space complexity of Method 1 is not `O(1)` precisely because it uses recursion. The reason for using recursion is that the pair of pointers `pre` and `cur` only works for one group. Find a way to make the pair work globally.

For iterative linked-list reversal, it is very simple: `pre` is always the predecessor of `cur`; adjust the relationship between `pre` and `cur`, then move both forward.

For groups of `k`, Method 1 uses recursion by group, so it can determine whether the final group has fewer than `k` nodes by counting the nodes in one group. This is inconvenient in the iterative method, because we also need to consider the case where the final group has already been reversed. Therefore, count the nodes first. Process one group at a time, decrease `n` by `k`, and stop when `n` is less than `k`, avoiding reversal of the final group with fewer than `k` nodes.

Iterative reversal needs at least three variables: predecessor `pre`, current node `cur`, and successor `nxt`. First let `cur` point to `pre` to reverse the relationship between them. Then assign the position of `cur` to `pre` and the position of `nxt` to `cur`, moving both forward and reversing again until the tail.

The key is connecting a reversed group to the previous and next groups. Suppose the list initially is:
```
1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> 8 -> 9
```

Let `k = 3`.

In general, suppose the first group has been reversed and we are processing the second group:
```
3 -> 2 -> 1 -> 4 -> 5 -> 6 -> 7 -> 8 -> 9
```

For iterative reversal, initially `pre` should be null and `cur` should be the head node, so here `pre` is 1 and `cur` is 4.

After reversing the second group:
```
                         pre cur
3 -> 2 -> 1 -> 4 <- 5 <- 6 -> 7 -> 8 -> 9
```

Here, the `next` of 4 is null because only the group was reversed; connection to the previous group has not been handled.

To connect to the previous group, record the tail of the previous group: 1 should point to 6.

To connect to the next group, record the head of the current group before reversal: 4 should point to 7.

For consistent management, create a dummy head node `dummy`, so every group follows the same logic. The list initially becomes:
```
d -> 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> 8 -> 9
```

For the first group, before it is correctly connected to the other groups, `dummy` acts as the “tail of the previous group”. But `dummy` always points to 3, while for other groups the tail of the previous group is not fixed. Therefore, declare a pointer `p` pointing to `dummy` in advance, separating the roles of `dummy` and “tail of the previous group”; use `p` to represent the latter.

After reversing the second group:
```
               p             pre  cur
d -> 3 -> 2 -> 1 -> 4 <- 5 <- 6 -> 7 -> 8 -> 9
```

The tail of the previous group and the original head of the current group are available as `p.next`.

Before making `p.next` point to 7, use `cgt` (current group's tail) to record the tail of the current group:
```
               p   cgt       pre  cur
d -> 3 -> 2 -> 1 -> 4 <- 5 <- 6 -> 7 -> 8 -> 9
```

Step 1: the original head becomes the tail after reversal, so make it point to the head of the next group. Make 4 point to 7, `cgt.next = cur`.

```
               p   cgt       pre  cur
d -> 3 -> 2 -> 1 -> 4 <- 5 <- 6 -> 7 -> 8 -> 9
                    |              ↑
                    |              |
                    ----------------
```

Step 2: the original tail becomes the head after reversal, so make the tail of the previous group point to it. Make 1 point to 6, `p.next = pre`.

```
               p   pre       cgt  cur
d -> 3 -> 2 -> 1 -> 6 -> 5 -> 4 -> 7 -> 8 -> 9
```

The connections to the previous and next groups are now correct. The next group is 7 8 9.

The role of `p` is “tail of the previous group”. For 7 8 9, the previous group is 4 5 6, whose tail is 4, so set `p = cgt`.

Then reverse 7 8 9 in the same way.

For easier understanding, before reversing the next group, set `pre` to null. This means “to avoid the first and second nodes of the current group pointing to each other during reversal, the initial `pre` has served as the successor of the first node after the first and second nodes were reversed”. In fact, this line is optional and only helps understanding.

```java
/**
 * Definition for singly-linked list.
 * public class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode() {}
 *     ListNode(int val) { this.val = val; }
 *     ListNode(int val, ListNode next) { this.val = val; this.next = next; }
 * }
 */
class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        // first count the nodes, n
        int n = 0;
        for(ListNode tmp = head; tmp != null; tmp = tmp.next) {
            n++;
        }

        // create a dummy head to act as the tail of the previous group for the first group
        ListNode dummy = new ListNode(0, head);

        // create p to represent the tail of the previous group for every group
        ListNode p = dummy;

        // predecessor for iterative reversal; pre is null before reversing each group
        ListNode pre = null;

        // current node for iterative reversal
        ListNode cur = head;

        // reverse in groups of k; decrease n by k and stop when n is less than k
        for(; n >= k; n -= k) {
            // the inner loop processes one group, from the first node through the kth node
            for(int i = 0; i < k; i++) {
                // reverse the pointers and move the two pointers forward together
                ListNode nxt = cur.next;
                cur.next = pre;
                pre = cur;
                cur = nxt;
            }

            // pre is the original tail of the current group, and cur is the head of the next group

            // the original head becomes the tail after reversal, so point it to the head of the next group
            ListNode cgt = p.next; // original head of the current group
            cgt.next = cur;

            // the original tail becomes the head after reversal, so point the previous tail to it
            p.next = pre;

            // before entering the next group, cgt is the tail of the current group and becomes p
            p = cgt;

            // keep pre null before reversing the next group
            pre = null;
        }

        return dummy.next;
    }
}
```
